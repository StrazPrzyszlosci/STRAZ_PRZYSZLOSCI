# Potential Pipeline: potencjał -> zamysł -> projekt -> wykonanie -> optymalizacja

Ten katalog przekłada wizję Straży Przyszłości na konkretny, audytowalny model pracy.

Automatyzacja nie zaczyna od „napisz losowy skrypt”. Zaczyna od pytania:

> Jaki darmowy lub tani potencjał istnieje wokół nas i jak zamienić go w użyteczne narzędzie dla ludzi?

Przykład: elektrośmieci są często darmowe, lokalnie dostępne i zawierają sensory, kamery, zasilacze, przewody, ekrany, smartfony, mikrokontrolery, radiatory, obudowy i mechanikę. Pipeline ma prowadzić od rozpoznania tego potencjału do projektu urządzenia potrzebnego np. do hydroponiki, akwaponiki, hodowli grzybów lub lokalnej logistyki.

## Etapy

1. **Analiza potencjału** — co jest dostępne, za darmo lub tanio, jaki ma wpływ społeczny i jakie ryzyka.
2. **Zamysł** — jaki produkt/usługa może powstać z zasobu i jaki problem rozwiązuje.
3. **Projekt** — jakie artefakty trzeba przygotować: BOM, schemat, firmware, obudowa, runbook, testy.
4. **Wykonanie** — tylko przez execution pack, z review i zapisanym audit trail.
5. **Optymalizacja** — pomiar wyniku, wnioski, poprawa skryptów, promptów i instrukcji.

## Zasada bezpieczeństwa

Dla żywności, wody, zwierząt, pomp, grzałek, przekaźników, dozowania chemii, wysokiego napięcia i radiokomunikacji pipeline domyślnie generuje tylko sugestie, projekty i testy bench. Deployment wymaga osobnego human approval.
